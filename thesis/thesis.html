The Core Concept

Manual penetration testing does not scale: it is expensive, bottlenecked by a shortage of skilled professionals, and vulnerable to human fatigue during long engagements. The industry's first attempt to fix this — coupling an LLM directly to security tools — trades one set of problems for another: LLMs face Context Saturation on massive raw tool outputs, Cognitive Drag from ever-growing command histories, and a brand-new attack surface in the form of Prompt Injection.

The proposed framework acts as an intelligent middleware orchestrator that bridges the high-level strategic reasoning of Large Language Models with the low-level execution of standard offensive security tools, emulating the cognitive and operational workflow of a human penetration tester. Instead of following traditional automated scanners that rely on a static execution tree, the system operates on a dynamic closed-loop architecture inspired by the "Observe, Orient, Decide, Act" (OODA) loop. By continuously interpreting tool outputs, updating its internal state, and adapting its strategy based on the target environment's evolving security posture, the agent interacts intelligently with the network. To ensure safe operation and command chain integrity, every LLM-generated decision is routed through a rigorous validation layer that checks against a whitelist of supported tools and prevents infinite execution loops.

To overcome the severe context saturation issues that typically plague LLM-based agents, the orchestrator relies on two primary innovation layers: Semantic Compression and Strategic Memory Hygiene. Semantic Compression specifically targets "Vertical Bloat" by acting as a domain-specific dispatcher; it distills massive raw datasets, such as verbose BloodHound JSON graphs or noisy HTML DOMs, into highly optimized, token-efficient textual representations. Simultaneously, the framework mitigates "Horizontal Bloat" — the linear accumulation of command history — by implementing a dynamic Recon Summary. This continuous Memory Hygiene ensures that the Context Management Layer only feeds high-signal, deduplicated information to the model, drastically reducing the LLM's cognitive drag and letting it focus on deep, forward-looking strategic pivoting rather than parsing historical noise.

Agentic Architecture

The system utilizes an Observe-Orient-Decide-Act Loop to manage the offensive lifecycle:

01
Observe

Execution of a security tool and collection of raw results directly from the target network or application.

02
Orient

Pre-processing and parsing of the raw data via the Semantic Compression Layer, followed by an update of the Recon Summary to maintain the current state of the assessment.

03
Decide

Presenting the summarized, noise-free context to the LLM so it can determine the next tactical objective or pivot point.

04
Act

Validating the LLM's decision against the tool whitelist and translating it into a correctly formatted command-line execution for the next tool in the chain.

The Observe-Orient-Decide-Act loop governing the offensive lifecycle.

Semantic Compression & Strategic Memory Hygiene

Every raw tool output first passes through a Semantic Compression pipeline: a tool dispatcher routes the raw stdout/stderr feed to one of sixteen dedicated parsing functions — from Nmap and NetExec to curl — which deterministically extract the signal via regex matching, key-field traversal, and metadata removal before state normalization generates a high-signal textual context for the LLM.

Deterministic pipeline turning raw tool logs into noise-free structured intelligence.
A raw Nmap scan distilled by the compression algorithm into a compact parsed-results block before reaching the prompt.

Complementing this, Strategic Memory Hygiene keeps the agent's working context clean over long engagements. Every execution, result, and error is persisted to a local SQLite ledger, from which a dynamic context window is drawn via SQL queries limited to the last errors and successes. Selective payload pruning discards outputs already consolidated into the state, and the resulting Recon Summary — capped to a sliding window of 3 recent errors and 5 recent successes — is what actually gets injected into the LLM's reasoning loop, preventing repeated steps and controlling token consumption.

Key Results

The experimental evaluation of the framework demonstrated significant improvements in operational scalability, efficiency, and security. By implementing the Semantic Compression layer, the system successfully mitigated "Vertical Bloat," cutting peak prompt size in the Active Directory lab from 38,339 to 4,418 tokens (>85% reduction) and in the Web Application lab from 23,234 to 6,465 tokens (>72% reduction). The introduction of Memory Hygiene via a dynamic Recon Summary then eliminated "Horizontal Bloat," cutting peak Thinking Token consumption from 10,773 to 1,961 tokens (~81% reduction) in the Active Directory scenario.

Quantitative Benchmarking

Beyond the single-shot ablations, the orchestrator was benchmarked end-to-end across 200 fully autonomous runs (50 runs per configuration), pitting Google Gemini 2.5 Flash against Gemini 3.0 Flash on both the Active Directory privilege-escalation lab and the Vulnerable Web Application lab. Both models reached a 100% success rate on the Active Directory lab at a cost of roughly $0.01–$0.02 per run; on the Web Application lab, Gemini 3.0 Flash also reached 100% success, while Gemini 2.5 Flash succeeded in 52% of runs — evidence that reasoning quality, not just orchestration, still matters for the hardest pivots.

Security Analysis: Indirect Prompt Injection

Autonomous agents operating in hostile environments face a threat that has no analogue in traditional software: the target environment itself can attack the agent. When an LLM ingests untrusted data—a file on a web server, an Active Directory object attribute, a crafted HTTP response—a malicious payload embedded in that data may be interpreted as a legitimate instruction, hijacking the agent's mission. This is known as Indirect Prompt Injection (IPI).

The naive assumption that fails

A common mitigation attempt is to wrap tool outputs in JSON, creating a syntactic boundary between data and instructions. Empirical testing across 30 automated runs shows this provides zero protection: both raw concatenation and JSON-wrapped output produced a 100% attack success rate. Structure alone is not a security boundary.

The framework addresses this with a Defense-in-Depth strategy across four architectural layers, all enforced by the orchestrator before untrusted content ever reaches the LLM agent: automatic output escaping, structural isolation, semantic compression as attack-surface reduction, and post-generation command validation against a strict whitelist.

Multi-layered deterministic filtering standing between the target environment's payload and the LLM agent.

Key insight: Cognitive Friction as a security signal

The spike in Thinking Tokens under V3 (averaging 1033, peaking at 2291 in the single failed run) is evidence that the orchestrator's structural constraints force the model to actively resolve the semantic conflict between trusted instructions and injected payload. The architecture makes attacks computationally expensive for the model to accept — and the single V3 failure required nearly 4× more reasoning overhead than successful V1 attacks.

30 targeted runs against Indirect Prompt Injection payloads: a 90-point drop in attack success rate under Defense-in-Depth.

The residual 10% failure rate underscores a fundamental constraint of current generative models: achieving deterministic IPI immunity at the model level is theoretically unfeasible, since LLMs process instructions and environmental data through the same attention mechanism. The framework's response is to shift the security guarantee from the model to the orchestration layer — making the agent robust by architecture, not by prompt engineering alone.
