The Core Concept

The proposed framework acts as an intelligent middleware designed to emulate the cognitive and operational workflow of a human penetration tester. Instead of following traditional automated scanners that rely on a static execution tree, the system operates on a dynamic closed-loop architecture inspired by the "Observe, Orient, Decide, Act" (OODA) loop. At its center is an autonomous orchestrator that bridges the high-level strategic reasoning of Large Language Models (LLMs) with the low-level execution of standard offensive security tools. By continuously interpreting tool outputs, updating its internal state, and adapting its strategy based on the target environment's evolving security posture, the agent interacts intelligently with the network. Furthermore, to ensure safe operation and command chain integrity, all LLM-generated decisions are routed through a rigorous validation layer that checks against a whitelist of supported tools and prevents infinite execution loops.

To overcome the severe context saturation issues that typically plague LLM-based agents, the system relies on two primary innovation layers: Semantic Compression and Strategic Memory Management. The Semantic Compression layer specifically targets "Vertical Bloat" by acting as a domain-specific dispatcher; it distills massive raw datasets, such as verbose BloodHound JSON graphs or noisy HTML DOMs, into highly optimized, token-efficient textual representations. Simultaneously, the framework mitigates "Horizontal Bloat"—the linear accumulation of command history—by implementing a dynamic Recon Summary. This continuous application of Memory Hygiene ensures that the Context Management Layer only feeds high-signal, deduplicated information to the model. Consequently, the system drastically reduces the LLM's cognitive drag, allowing the underlying model to focus exclusively on deep, forward-looking strategic pivoting rather than wasting compute on parsing historical noise.

Agentic Architecture

The system utilizes a Observe-Orient-Decide-Act Loop to manage the offensive lifecycle:

01
Observe

Execution of a security tool and collection of raw results directly from the target network or application.

02
Orient

Pre-processing and parsing of the raw data via the Semantic Compression Layer, followed by an update of the Recon Summary to maintain the current state of the assessment.

03
Decide

Presenting the summarized, noise-free context to the LLM so it can determine the next tactical objective or pivot point.

04
Act

Translating the LLM's high-level decision into a correctly formatted and validated command-line execution for the next tool in the chain.

High-level architecture of the LLM-powered pentest agent.

Key Results

The experimental evaluation of the framework demonstrated significant improvements in operational scalability, efficiency, and security. By implementing the Semantic Compression layer, the system successfully mitigated "Vertical Bloat," reducing the token footprint of raw tool outputs—such as complex BloodHound Active Directory graphs—by over 85%. This distillation prevented context saturation and preserved the model's ability to execute deep, graph-based strategic reasoning. Furthermore, the introduction of Memory Hygiene via a dynamic Recon Summary effectively eliminated "Horizontal Bloat," cutting peak Thinking Token consumption by 81% in Active Directory scenarios.

Security Analysis: Indirect Prompt Injection

Autonomous agents operating in hostile environments face a threat that has no analogue in traditional software: the target environment itself can attack the agent. When an LLM ingests untrusted data—a file on a web server, an Active Directory object attribute, a crafted HTTP response—a malicious payload embedded in that data may be interpreted as a legitimate instruction, hijacking the agent's mission. This is known as Indirect Prompt Injection (IPI).

The naive assumption that fails

A common mitigation attempt is to wrap tool outputs in JSON, creating a syntactic boundary between data and instructions. Empirical testing across 30 automated runs shows this provides zero protection: both raw concatenation and JSON-wrapped output produced a 100% attack success rate. Structure alone is not a security boundary.

The framework addresses this with a Defense-in-Depth strategy across four architectural layers: automatic output escaping, structural isolation via TOON (Task-Oriented Output Notation) encoding, semantic pruning as attack surface reduction, and post-generation command validation against a strict whitelist.

Key insight: Cognitive Friction as a security signal

The spike in Thinking Tokens under V3 (averaging 1033, peaking at 2291 in the single failed run) is evidence that the orchestrator's structural constraints force the model to actively resolve the semantic conflict between trusted instructions and injected payload. The architecture makes attacks computationally expensive for the model to accept — and the single V3 failure required nearly 4× more reasoning overhead than successful V1 attacks.

The residual 10% failure rate underscores a fundamental constraint of current generative models: achieving deterministic IPI immunity at the model level is theoretically unfeasible, since LLMs process instructions and environmental data through the same attention mechanism. The framework's response is to shift the security guarantee from the model to the orchestration layer — making the agent robust by architecture, not by prompt engineering alone.
